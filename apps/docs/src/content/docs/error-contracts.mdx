## Error Contract

The Data360 API uses exactly **3 types of errors** for consistent, predictable error handling:

| HTTP Code | Type | When |
|-----------|------|------|
| **500** | Server Error | Backend down or unhandled exception |
| **400 / 404** | Connection Error | Snowflake not connected, session expired, resource not found |
| **422** | Snowflake SQL Error | SQL compilation or execution error from Snowflake |

Additional codes: `401` (not authenticated), `403` (access denied), `429` (rate limited).

---

## 500 — Server Error

The backend is down or encountered an unhandled exception.

```json
{
  "detail": "Internal server error",
  "error_type": "unknown"
}
```

**Action:** Check that the server is running. Review backend logs.

---

## 400 — Validation / Connection Error

Snowflake is not connected, the session expired, or request parameters are invalid.

```json
{
  "success": false,
  "detail": [],
  "message": "Missing or invalid fields",
  "error_type": "validation",
  "fields_required": ["account_name", "username", "password"],
  "data": {
    "required_fields": [],
    "validation_errors": []
  }
}
```

**Action:** Check your connection. Re-authenticate if needed. Fix invalid parameters.

---

## 404 — Not Found

The requested resource doesn't exist in Snowflake or the account is unreachable.

```json
{
  "detail": "Not found"
}
```

---

## 401 — Not Authenticated

No token provided, or the token is invalid/expired.

```json
{
  "detail": "Not authenticated. Sign in via POST /signin.",
  "error_code": "UNAUTHORIZED"
}
```

**Action:** Call `POST /signin` to get a new token, then retry with `Authorization: Bearer <new_token>`.

---

## 403 — Access Denied

Your Snowflake role doesn't have permission for this operation.

```json
{
  "detail": "Permission denied."
}
```

---

## 422 — Snowflake SQL Error

A SQL query failed in Snowflake. The response includes the full Snowflake error with `errno`, `sqlstate`, and the error message.

```json
{
  "detail": "000904 (42000): 01c2423a-0306-0cd1-0004-74b2001dd1d6: SQL compilation error: invalid identifier 'EVENT_DATE'",
  "error_type": "snowflake",
  "message": "000904 (42000): SQL compilation error: invalid identifier 'EVENT_DATE'",
  "snowflake": {
    "errno": 904,
    "sqlstate": "42000",
    "msg": "SQL compilation error: invalid identifier 'EVENT_DATE'"
  }
}
```

**Action:** Fix the SQL query. Common causes:
- Invalid column/table names (`errno 904`)
- Permission denied on object (`errno 1003`)
- Warehouse suspended (`errno 604`)

<Aside type="tip">
  The `snowflake.errno` and `snowflake.sqlstate` fields help you programmatically categorize errors. See [Snowflake SQL Error Codes](https://docs.snowflake.com/en/developer-guide/snowflake-scripting/exceptions#error-codes) for the full list.
</Aside>

## Error Handling Best Practices

```python
import requests

response = requests.get(
    "https://api.datalab360.io/command-center/summary",
    headers={"Authorization": f"Bearer {token}"}
)

if response.status_code == 200:
    data = response.json()
elif response.status_code == 401:
    # Re-authenticate
    token = refresh_token()
    # Retry the request
elif response.status_code == 422:
    error = response.json()
    sf = error.get("snowflake", {})
    print(f"Snowflake error {sf.get('errno')}: {sf.get('msg')}")
elif response.status_code >= 500:
    print("Server error — retry later")
else:
    print(f"Error {response.status_code}: {response.json().get('detail')}")
```

## Response Metadata

All JSON responses include execution timing via the `X-Execution-Time-Ms` header:

```
HTTP/1.1 200 OK
X-Execution-Time-Ms: 142
Content-Encoding: gzip
Content-Type: application/json
```

Responses larger than 1000 bytes are automatically GZip compressed.
